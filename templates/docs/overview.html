Overview

Nagios Bulk Editor is a web application for managing Nagios monitoring configurations at scale. It reads your .cfg files, parses every object definition, and presents them in a browsable, editable interface — so you can make sweeping changes across hundreds of hosts, services, and templates without hand-editing raw config files.

Key Capabilities

Visual Object Explorer

A three-pane layout lets you browse every Nagios object type — hosts, services, commands, contacts, timeperiods, templates, and more. The left pane shows a tree of config files and folders. The center pane lists the objects in the selected file. The right pane is an attribute editor for the selected object.

Bulk Editing

Select multiple objects at once and edit shared attributes in a single operation. Use find & replace to update values across your entire configuration. Changes propagate instantly across all selected objects.

Staging System

All changes are held in memory — nothing is written to disk until you explicitly click Apply. You can review every pending change, undo individual edits, or clear all staged changes at any time.

Git Integration

View diffs of your staged changes, commit directly from the UI, and track your configuration's version history. The commit dialog shows a complete diff of every change before you confirm.

File Management

Create, move, rename, and delete config files and folders from within the app. Move objects between files by dragging them in the explorer. Create new files and folders to reorganize your configuration structure.

Validation

Run nagios -v directly from the UI to verify your configuration is valid before reloading Nagios. Validation output is displayed inline so you can identify and fix errors without leaving the app.

How It Works

When the app starts, it reads all .cfg files in your configured Nagios directory and parses every define { ... } block into structured objects. These objects are presented in the Object Explorer where you can browse, search, and edit them.

As you make changes — editing attributes, moving objects, creating or deleting files — each change is recorded in the staging system. Nothing touches your config files on disk. You can review the full list of pending changes in the commit dialog, undo anything you don't want, and refine your edits until you're satisfied.

When you click Apply, all staged changes are written atomically to disk. If Git is configured, you can then commit the changes with a message describing what you did.

The staging system makes it safe to experiment. Since no changes are written to disk until you click Apply, you can freely explore edits, undo them, and try different approaches without any risk to your live configuration.

Architecture at a Glance

Nagios Bulk Editor is a Flask application with a vanilla JavaScript frontend. The backend is organized as a set of service classes — parsing, staging, file operations, Git, backups, validation — each with a clear responsibility. The frontend communicates with the backend through a REST API.

There is no database. All state comes from the filesystem: your Nagios .cfg files are the source of truth, and staged changes are held in server memory until applied. Configuration settings are stored in a single JSON file.

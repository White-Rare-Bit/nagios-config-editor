File & Folder Management

Nagios configuration is organized into .cfg files within folders. The Workspace tab in the right pane of the Object Explorer gives you full control over this file structure: create, move, rename, and delete files and folders, all through a familiar tree interface.

All file and folder operations are staged, not immediately written to disk. Nothing changes until you click Apply in the commit dialog. See Staging System for details.

The Workspace Tab

The workspace tab lives in the right pane of the Object Explorer, alongside the Relations and Analysis tabs. It displays a tree of all .cfg files and folders in your Nagios configuration directory. The tree header shows the root folder name and total object count.

At the top of the workspace tree you will find toolbar buttons for:

  • New File — creates a new .cfg file in the currently selected folder (or root)
  • New Folder — creates a new subfolder in the currently selected folder (or root)
  • Collapse All — collapses every folder in the workspace tree
  • Refresh — reloads the workspace tree from the server

Creating Files

To create a new configuration file, click the New File button in the workspace toolbar. An inline text input appears where you type the filename. Press Enter to confirm or Escape to cancel.

  • Filenames must end in .cfg — the extension is added automatically if you omit it.
  • Invalid characters (/ \ : * ? " < > |) are rejected.
  • The file is created inside whichever folder is currently selected in the workspace tree. If no folder is selected, it is created in the config root.
  • New files appear in the tree immediately with a staged indicator, but they do not exist on disk until you apply.

Creating Folders

Click the New Folder button and type a name in the inline input. The same validation rules apply (no special characters). Folders are staged the same way as files.

Moving Files

You can move a .cfg file to a different folder in two ways:

  1. Drag and drop — drag a file row in the workspace tree and drop it onto a target folder. The folder highlights when you hover over it. Hovering over a collapsed folder for 800 ms will auto-expand it.
  2. API-level move — the application sends a POST /api/files/move request with the source path and target folder. The move is staged, not immediate.

When a file is moved, all objects inside it retain their attributes — only the file path changes. The move appears in the commit dialog so you can review it before applying.

Moving Folders

Entire folders can be moved to a new parent folder via drag and drop in the workspace tree. The same auto-expand behavior applies: hover over a collapsed target folder while dragging to open it.

  • A folder cannot be moved into itself or into one of its own descendants.
  • All files and subfolders inside the moved folder come along. Object paths update automatically.

Deleting Files

Click the delete icon next to a file in the workspace tree to stage it for deletion. If the file contains objects, a confirmation dialog explains that all objects in the file will be removed.

  • Staged file deletions appear with a strikethrough style in the workspace tree.
  • If you have staged moves that target the file being deleted, the application warns you about the conflict.
  • New files that have not been applied yet can be removed immediately (they are simply unstaged).

Deleting Folders

Click the delete icon on a folder row to stage it for deletion. The config root directory cannot be deleted. As with file deletions, a confirmation prompt appears if the folder contains files or objects.

Deleting a folder also deletes every file and subfolder within it. Make sure you have reviewed the contents before confirming.

Moving Objects Between Files

Beyond moving entire files, you can move individual Nagios objects from one file to another. There are two ways to do this:

  1. Drag and drop — select one or more objects in the center pane, then drag them onto a file in the workspace tree. A drop indicator shows where the objects will land.
  2. Context menu — right-click selected objects in the center pane and choose Move to file.... A dialog lets you pick the target file from a dropdown.

When objects are moved between files, the staging system records the original file, target file, and insertion position. The commit dialog shows the move as a removal from the source file and an addition to the target file, making it easy to review.

Staged Indicators

The workspace tree uses visual indicators to show what has been staged:

Indicator Meaning
Green highlight Newly created file or folder (staged, not yet on disk)
Strikethrough File or folder staged for deletion
Move arrow File or folder staged to move to a new location

All file and folder changes flow through the Staging System and appear in the commit dialog alongside object-level changes, giving you a complete picture before writing anything to disk.

Configuration

Application settings are stored in config/settings.json. The configuration system supports three levels of precedence, from highest to lowest:

  1. Environment variables — Override everything
  2. Config file — config/settings.json
  3. Default values — Built into the ServerConfig dataclass

If no config file exists on first run, one is created automatically with default values.

Configuration Structure

The config file is a JSON document with two sections: paths and logging.

Path Settings

Field Type Default Description
nagios_config_path str "./sample-config" Path to the directory containing Nagios .cfg files
backup_path str | null null Custom path for storing backups (defaults to a backups/ subdirectory inside the config path)
nagios_bin str "/usr/local/nagios/bin/nagios" Path to the Nagios binary (for nagios -v validation)
nagios_cfg str "./sample-config/nagios.cfg" Path to the main nagios.cfg file (used by validation)
resource_cfg str "" Path to a resource.cfg file (for macro resolution)

Logging Settings

Field Type Default Description
enabled bool true Whether operation logging is enabled
log_level str "INFO" Logging level (DEBUG, INFO, WARNING, ERROR)
log_dir str "logs" Directory for log files
log_filename str "operations.jsonl" Log file name (JSON Lines format)
max_file_size_mb int 10 Maximum log file size before rotation (MB)
max_backup_files int 5 Number of rotated log files to keep

Example Config File

{
  "version": 1,
  "paths": {
    "nagios_config_path": "/etc/nagios/objects",
    "backup_path": null,
    "nagios_bin": "/usr/local/nagios/bin/nagios",
    "nagios_cfg": "/etc/nagios/nagios.cfg",
    "resource_cfg": ""
  },
  "logging": {
    "enabled": true,
    "log_level": "INFO",
    "log_dir": "logs",
    "log_filename": "operations.jsonl",
    "max_file_size_mb": 10,
    "max_backup_files": 5
  }
}

Environment Variable Overrides

Environment variables take the highest precedence. When set, they override both the config file and default values. Changes via environment variables are applied at load time and are not persisted to the config file.

Environment Variable Overrides
NAGIOS_CONFIG_PATH paths.nagios_config_path (normalized to absolute path)
BACKUP_PATH paths.backup_path
NAGIOS_BIN paths.nagios_bin
NAGIOS_CFG paths.nagios_cfg
The nagios_config_path is always normalized to an absolute path, whether set via environment variable or config file. Relative paths are resolved against the application's working directory.

Config Loading

Configuration is loaded by load_config() in server_config.py. The loading process:

  1. Ensure the config/ directory exists
  2. Start with default ServerConfig values
  3. If config/settings.json exists, parse it and overlay onto defaults
  4. Apply environment variable overrides
  5. If no config file existed, create one with the resolved values

The config is saved atomically using the same temp-file + os.replace() pattern used throughout the application.

Updating Configuration

Configuration can be updated in two ways:

Settings Page

The Settings page provides a UI for editing paths and logging configuration. Changes made here are saved to config/settings.json via POST /api/settings.

Programmatic Updates

The update_config(updates) function accepts a dictionary of updates, supports both flat and nested key formats: 

# Flat keys (backward compatibility)
update_config({'nagios_config_path': '/new/path'})

# Nested keys
update_config({'paths': {'nagios_config_path': '/new/path'}})

# Logging updates
update_config({'logging': {'log_level': 'DEBUG'}})

The function loads the current config, applies updates, saves, and returns the updated ServerConfig.

Environment variables always take precedence on the next load_config() call. Saving a config file does not override environment variables — the env var will win again when the config is reloaded.

Config Schema Version

The config file includes a version field (currently 1) for future schema migrations. When saving, the version is always updated to the current CONFIG_VERSION.

The backend is organized into service classes, each responsible for a single domain. All services are instantiated during app creation and stored in app.extensions. Route handlers access them via helper functions like get_service() and get_staging_manager().

Service Overview

Service Module Responsibility
NagiosService nagios_service.py CRUD operations on Nagios objects, apply phases for staging
StagingManager staging_manager.py Staging state, session locks, undo stack, conflict detection
GitService git_service.py Git subprocess wrapper, retry logic, identity injection
BackupManager backup_manager.py Zip backup creation, restore, cleanup
NagiosParser nagios_parser.py Parse .cfg files, object lookups
NagiosWriter nagios_writer.py Write .cfg files with atomic writes

NagiosService

The primary service for interacting with Nagios configuration objects. Handles all CRUD operations and the multi-phase apply process for staging. All mutation methods acquire a multiprocessing.Lock to ensure thread safety.

StagingManager

Manages the staging lifecycle: lock acquisition, staged operation storage, undo stack, and conflict detection. Internally delegates to composed managers:

  • sm.checksums (ChecksumManager) — file checksums and conflict detection
  • sm.undo (UndoStackManager) — undo stack operations
  • sm.file_ops (FileOperationsStager) — file/folder staging operations

GitService

Wraps all Git operations in subprocess calls with timeout management, retry logic for transient errors, and per-operation identity injection. Multi-step mutations are serialized via a multiprocessing.Lock.

Retry Logic

The internal _run_git() method implements exponential backoff for transient Git lock errors. If the error output contains patterns like index.lock, unable to create, or cannot lock ref, the operation is retried up to 3 times with increasing delays.

Timeout Presets

Preset Timeout Used For
TIMEOUT_QUERY 5 seconds rev-parse, config lookups
TIMEOUT_STATUS 10 seconds status, reset, branch
TIMEOUT_MUTATE 30 seconds commit, checkout, clean, add, diff

Identity Injection

Git user identity is passed per-operation rather than stored in global config. The commit method executes: 

git -c user.name="John Doe" -c user.email="john@example.com" commit -m "message"

This ensures each commit is attributed to the correct user without modifying the system's Git configuration.

NagiosWriter

Handles writing Nagios configuration back to .cfg files. All writes use an atomic pattern to prevent data corruption:

  1. Write to a temporary file in the same directory
  2. Call flush() and os.fsync() to ensure data reaches disk
  3. Use os.replace() for an atomic rename (POSIX guarantee)

Block editing uses find_block_range() to locate the character offsets of a define { ... } block by line number, then rewrites the file with the updated block content. The block range finder handles nested braces, quoted strings, and escape sequences.

Path Safety

All file and folder operations pass through is_safe_path(path, base_dir) before execution. This function checks for:

  • Null byte injection
  • Path traversal attempts (.. in path)
  • Symlink resolution (ensures the resolved path stays within the base directory)
  • Base directory containment (the final resolved path must be under the config directory)
Critical: Never bypass is_safe_path() when adding new file operations. It is the primary defense against directory traversal attacks.

Contributing

This guide covers the conventions, patterns, and processes for contributing to Nagios Bulk Editor.

Code Style

Language Convention Examples
Python snake_case get_staging_info, staging_manager, apply_object_composite
JavaScript camelCase getStagingInfo, refreshAfterObjectChange, buildTypeDropdown
CSS classes kebab-case docs-prose, commit-dialog, lock-banner
CSS variables --nbe-* prefix --nbe-bg-primary, --nbe-text-muted, --nbe-dark-bg-primary

API Field Names

The REST API uses snake_case for all field names in both requests and responses. The frontend preserves API field names in requests (it does not convert to camelCase when sending data to the backend).

Backend Patterns

OperationResult

All service methods that perform mutations must return an OperationResult. Never raise exceptions from service methods — catch them and return OperationResult(success=False, error=str(e)). 

def my_service_method(self, param):
    try:
        # do work...
        return OperationResult(success=True, data=result_data)
    except Exception as e:
        return OperationResult(success=False, error=str(e))

Backup Before Mutation

Any operation that writes to disk must create a backup first: 

bm.create_backup("pre_operation_name")

Lock Check for Staging Mutations

Route handlers that modify staging state must verify session ownership: 

if not sm.can_modify(request.headers.get('X-Session-Id')):
    return jsonify({'error': 'Locked by another user', 'locked': True}), 423

Parser Modification

When multiple parser mutations need to run atomically, use the context manager: 

with get_parser_for_modification() as p:
    # multi-step mutation — lock is held, parser reloads on exit

Frontend Patterns

Event Delegation

Use data-action attributes on HTML elements and dispatch via an actionHandlers map. Do not bind event listeners to individual elements that will be re-rendered: 

// Good: event delegation
<button data-action="saveObject">Save</button>
actionHandlers.saveObject = (el) => { ... };

// Avoid: direct binding (breaks on re-render)
document.querySelector('.save-btn').addEventListener('click', ...);

API Calls

Always use ApiClient.get() or ApiClient.post() for API calls. Never use raw fetch(). The ApiClient handles session headers, JSON serialization, and error normalization: 

const result = await ApiClient.post('/api/staging', { data: payload });
if (!result.success) {
    showToast(result.error, 'danger');
    return;
}
// use result.data

Testing

Running Tests

Tests use pytest. Run the full suite from the project root: 

python3 -m pytest tests/ -v

The test suite runs fast (under 1 second for the full suite).

Test Structure

Tests are organized in the tests/ directory. Each test module typically tests a single service or route module. Tests use Flask's test client for API endpoint testing and direct service instantiation for unit tests.

Adding a New Object Type

To add support for a new Nagios object type (for example, a custom object definition):

  1. Update nagios_model.py — Add the type to the relevant domain constants:
    • NAME_FIELDS — Which attribute holds the object's name
    • REFERENCE_FIELDS — Which attributes reference other objects
    • REQUIRED_FIELDS — Mandatory attributes for the type
    • NAGIOS_ATTRIBUTES — All known attributes
    • DEFAULT_ATTRIBUTES — Attributes shown when creating a new object
  2. That is it. The frontend fetches metadata from GET /api/metadata at startup and picks up the new type automatically. No JavaScript changes needed.
The domain metadata system is designed as a single source of truth. All Nagios object type information is defined once in nagios_model.py, served via the metadata API, and consumed by the frontend at startup. Never hardcode domain metadata in JavaScript files.

CSS Token System

All colors, spacing, and typography values should use design tokens from tokens.css. Tokens use the --nbe- prefix:

Light Theme Tokens

--nbe-bg-primary        /* Main background */
--nbe-bg-secondary      /* Secondary background */
--nbe-text-primary      /* Main text color */
--nbe-text-muted        /* De-emphasized text */
--nbe-border-primary    /* Standard border */
--nbe-accent-primary    /* Brand/accent color */

Dark Theme Tokens

Dark theme tokens follow the pattern --nbe-dark-{category}-{variant} and are currently used on the Explorer page only: 

--nbe-dark-bg-primary
--nbe-dark-bg-secondary
--nbe-dark-text-primary
--nbe-dark-border-primary

Categories include: bg, text, border, accent, input, btn, tab, validation.

Button System

Use the .nbe-btn base class with modifiers:

  • Variants: --filled, --outlined, --danger, --info, --ghost
  • Sizes: --xs, --sm, (default), --lg
  • Modifiers: --icon (square), --full (full width), .nbe-btn-group
  • Dark theme: Add --dark (e.g., .nbe-btn--dark.nbe-btn--filled)
  • Loading state: Set data-loading="true" via JavaScript

Typography Tokens

Semantic typography groups each provide -size, -weight, and -line-height variants:

  • h1 (20px), h2 (16px), h3 (14px)
  • label (12px/600), body (13px), secondary (12px), muted (10px)
  • code (12px/mono), badge (10px/600)
  • button (13px), button-sm (12px), input (13px)

Fonts: Inter (--nbe-font-sans) and JetBrains Mono (--nbe-font-mono), both bundled as woff2 files.

Structured Logging

Backend operations use the OperationLogger for structured JSON logging. Log entries include the module, operation, parameters, and result: 

if op_logger:
    op_logger.info('service', 'create_object',
                   params={'file': file_path, 'obj_type': obj_type},
                   result='success')
    op_logger.error('service', 'create_object',
                    params={'file': file_path},
                    error=str(e))

Log levels: DEBUG (parser reload), INFO (successful operations), WARNING (retries, partial failures), ERROR (failures).

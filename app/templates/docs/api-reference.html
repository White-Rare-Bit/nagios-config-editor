API Reference

All API endpoints return JSON. Mutation endpoints require a session ID sent via the X-Session-Id header for shadow copy lock validation. Field names in both requests and responses use snake_case.

Pages

HTML page routes serve rendered templates. The root path redirects to /explorer.

Route Method Description
/ GET Redirect to /explorer
/explorer GET Object Explorer (three-pane layout)
/git GET Git page with diff viewer
/backups GET Backup management
/dependencies GET Cytoscape dependency graph
/logs GET Unified log viewer (audit + application)
/settings GET Settings and configuration
/docs GET In-app documentation

Metadata

Route Method Description
/api/metadata GET All Nagios domain metadata (type labels, name fields, required fields, reference fields, attributes, etc.)
The metadata endpoint is the single source of truth for all Nagios domain constants. The frontend fetches it once at startup. Never hardcode domain metadata in JavaScript.

Objects

Route Method Description
/api/objects GET List objects with optional type and search query filters
/api/objects/update POST Update attributes of an existing object (by stable key)
/api/objects/create POST Create a new object in the specified file
/api/objects/delete POST Delete a single object (by stable key)
/api/objects/move POST Move an object to a different file
/api/objects/delete-multiple POST Delete multiple objects, with optional reference cleanup

Shadow Copy & Staging

Route Method Description
/api/staging GET Get shadow copy status and change summary
/api/staging DELETE Destroy shadow copy and release lock (discard all changes)
/api/staging/info GET Shadow copy summary with change counts, undo count (used for polling)
/api/staging/lock GET Get lock status (locked, session_id, user_name, user_email)
/api/staging/lock/break POST Force break the lock and destroy shadow copy (admin action)
/api/staging/apply POST Replace original config with shadow copy. Detects conflicts; accepts force param to override. Returns 409 on conflict.
/api/staging/undo POST Restore files from the most recent undo snapshot
/api/staging/diff GET Per-file unified diffs (shadow vs original) for the commit dialog

Request Format

All POST endpoints accept JSON request bodies. Mutation endpoints that modify the shadow copy must include the X-Session-Id header. The frontend's ApiClient adds this header automatically.

Response Format

Successful responses return: 

{"success": true, "data": { ... }}

Error responses return: 

{"error": "Description of what went wrong"}

The HTTP status code indicates the error category (400, 404, 409, 423, or 500). See Architecture for the full status code reference.

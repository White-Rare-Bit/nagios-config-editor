Configuration Ancestry

The Configuration Ancestry section appears as a collapsible accordion in the object editor. Click the header to expand or collapse it. It contains three subsections:

Templates

Shows the template inheritance chain as a horizontal flow, reading left to right from the root template to the selected object. Each item in the chain displays a type badge (e.g. "HOST TEMPLATE" or "HOST") followed by the object name. Arrows connect the chain items.

Clicking any item in the chain navigates to that object. If a template referenced in the use directive does not exist, the chain shows that item with an error indicator ().

Network Parents

For host objects, shows the network parent hierarchy using the same horizontal pill layout. Missing parents are highlighted with a danger border and an icon.

Resolved Attributes

A three-column table showing the final resolved attribute set after all inheritance is applied. This is what Nagios will actually use at runtime:

Column Description
Attribute The directive name, sorted alphabetically.
Value The resolved value that Nagios will use.
Source Which object or template provides this value. Attributes defined directly on the object show the object name; inherited values show the template name (highlighted in the accent color).
Nagios inheritance uses a "first match wins" rule: if both a child and a parent template define the same attribute, the child's value takes precedence. The resolved attributes table reflects this behavior.

Use Cases

  • Debugging inheritance issues — see exactly which template provides a specific value and whether the child overrides it.
  • Understanding template structure — visualize multi-level template chains before making changes.
  • Identifying missing templates — the chain flags templates that are referenced but do not exist.

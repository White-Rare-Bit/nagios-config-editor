Editing Objects

The attribute editor in the center pane lets you modify every directive on a Nagios object. Changes are staged immediately as you type — nothing is written to disk until you apply through the Staging System.

Editor Layout

When you select an object, the center pane shows:

  • A header with the object type, name, and source file.
  • An issue badge if the object has validation problems (missing references, duplicates, etc.). Click the badge to jump to the issue in the Suggestions tab.
  • The attribute table — one row per directive, with the attribute name on the left and an editable value field on the right.
  • An Impact & Relationships section (collapsed by default) showing inheritance chains, references, and dependents.

Editing Attribute Values

Click on any attribute value field to edit it. Changes are staged automatically when you move focus away from the field (on blur) or press Enter. The staging indicator in the navbar updates to reflect the pending change.

Short attribute values use a single-line text input. Long values — such as command_line, alias, notes, and notes_url — use a resizable textarea with syntax highlighting for command syntax (macros like $HOSTADDRESS$, flags, paths, and pipe operators are color-coded).

Reverting a Change

If you edit a value back to its original content, the pending edit for that object is automatically removed from staging. You can also use Ctrl+Z (Cmd+Z on Mac) to undo the last staging operation.

Required Fields

When you edit an object, the editor validates that required fields are present. If a required field is missing and the object does not inherit from a template (via the use directive), a warning toast appears. Objects that use templates get a softer warning since the template may provide the missing fields through inheritance.

Required fields vary by object type. For example, a host requires host_name, while a service requires service_description plus either host_name or hostgroup_name. Templates (objects with register 0) always require the name attribute.

Adding Attributes

To add a new directive to an object, click the Add Attribute button below the attribute table. This opens a dialog with two fields:

  1. Name — an autocomplete dropdown showing all valid directives for the current object type. Type to filter, or scroll through the full list. Only directives not already present on the object are shown.
  2. Value — enter the value for the directive. If the attribute is a reference field (like check_command or use), the value field also provides autocomplete with matching objects.

Removing Attributes

Each attribute row has a delete button (×) on the right side. Click it to remove the directive from the object. The removal is staged immediately.

You can also copy an attribute's value to the clipboard using the copy button next to the delete button.

Reference Fields and Autocomplete

Certain attributes reference other Nagios objects by name. When you edit one of these fields, an autocomplete dropdown appears showing matching objects of the correct type. Reference fields include:

  • use — shows templates of the same object type (objects with register 0).
  • check_command, event_handler — shows command objects.
  • host_name (on services) — shows host objects.
  • hostgroup_name, servicegroup_name — shows the corresponding group objects.
  • contacts, contact_groups — shows contact and contactgroup objects.
  • check_period, notification_period — shows timeperiod objects.
  • members (on groups) — shows objects of the member type for that group.

For comma-separated reference fields (like contacts or host_notification_commands), the autocomplete filters out values you have already entered so you do not accidentally add duplicates.

Validation on Reference Fields

When you set a reference field to a value that does not match any existing object, the editor shows an error toast and reverts the field to its previous value. This prevents broken references from being staged. Command attributes support the Nagios argument syntax (command_name!arg1!arg2) — only the command name portion before the first ! is validated.

Notification Options

Notification option fields (notification_options, host_notification_options, service_notification_options, escalation_options, etc.) show a dropdown with the valid short codes and their descriptions (e.g. d - Down, r - Recovery). The autocomplete inserts only the short code into the field.

Attribute Documentation Popover

Hover over any attribute name in the editor to see a documentation popover. The popover shows the directive's format, whether it is required or optional, and a brief description. Click the "View in docs" link in the popover to jump to the full reference documentation.

Creating New Objects

Click the + button on a file header in the tree to create a new object in that file. A new object form appears in the center pane with:

  • A type selector — dropdown to choose the object type (host, service, command, etc.).
  • A name input — enter the primary name for the object.
  • Default attributes — pre-populated based on the selected type.

The new object is staged immediately and appears in the tree with a green "+" badge. You can continue editing its attributes just like any existing object. Change the object type at any time using the type dropdown — the name is preserved and the default attributes update to match the new type.

The editor validates new object names for uniqueness. If you enter a name that already exists (either on disk or in another staged creation of the same type), an error toast appears and the change is rejected.

Inheritance Display

If an object uses template inheritance (via the use directive), the Impact & Relationships section shows the full inheritance chain as a breadcrumb trail from the root template to the current object. Below the chain, a table lists all inherited attributes with their values. Attributes that the current object overrides are marked with an "Overridden" badge.
